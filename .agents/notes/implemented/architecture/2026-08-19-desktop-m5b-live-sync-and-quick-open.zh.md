# Agent Note: 桌面 M5B 实时同步、外部变更处理与快速打开

Status: implemented

[English](2026-08-19-desktop-m5b-live-sync-and-quick-open.md) | 中文

## Problem

M5A 编辑器通过 ctx.fs 打开缓冲区并使用 FsVersion 守卫保存，但没有任何机制在文件被底层修改时通知 UI：外部编辑器、Finder、集成终端或 harness 代理本身都可能重写文件，而打开的缓冲区保持过期；Files 与 Changes 仍依赖手动刷新按钮；带未保存更改退出时会无条件停止运行时。

## Decision

M5B 增加一个原生的、非权威的变更来源：由运行时管理器拥有的 Rust 工作区监听器（notify crate），限定在当前工作区，随每个运行时 generation 启动并随其停止。它通过 `workspace://changed` Tauri 事件发出仅含路径的失效批次（绝不携带内容或版本），100 ms 合并、512 路径洪泛上限；被上限截断的批次标记为 `full`，使所有表面失效。前端再次以 150 ms 合并、丢弃过期 generation，并分发到 Files、Changes、编辑器与快速打开。编辑器按缓冲区对账：干净的缓冲区自动重载并保持干净；脏缓冲区保留草稿并呈现外部变更冲突（Review/Reload 与 Keep my changes）；删除的文件保留标签页并进入 deleted 状态，绝不自动重建；瞬态缺失（尚无活动会话）绝不会判定为删除。其长生命周期的 CodeMirror 视图从 ref 读取当前活动路径，因此切换标签页后的编辑只会标记当前显示的标签页。对账会在异步 stat 完成后重新读取缓冲区，因此刚完成的 FsVersion 守卫保存会采用其返回版本，而不会被标记为自身造成的外部变更。运行时重连后，打开的缓冲区在 UI 内存中存活，并在会话重新可用后对账。FsVersion 仍是唯一的数据权威：监听器绝不决定内容或版本。

快速打开（Cmd+P）是内存中的仅路径索引：在 git 仓库内，宿主通过 `git ls-files --cached --others --exclude-standard` 构建（NUL 分隔、遵循 .gitignore、固定 argv）；非 git 场景下是受限遍历，跳过 .git/.DS_Store，绝不深入符号链接目录，上限 200,000 个文件。构建在阻塞线程池执行，过期结果被丢弃。

未保存更改退出守卫 fail-closed：缓冲区为脏、正在保存、冲突或保存错误时前端都武装原生守卫；退出尝试（Cmd+Q 或关闭窗口）在 Rust 侧、任何运行时拆除之前被阻止，并呈现给对话框：取消、放弃并退出、全部保存并退出（仅当每个 FsVersion 守卫保存成功时才退出）。

上游 `fs/observed` 已验证但未转发：它只在 harness 工具操作经过 ctx.fs 时触发，因此看不到 Finder、终端或外部编辑器，且其载荷到达 UI 时可能已过期。原生监听器在同一文件系统上看到相同的写入，因此只有一个事件源和一个状态模型。

## Alternatives considered

### 为何不转发 fs/observed 而增加监听器？

fs/observed 是写/编辑意图瀑布流的观察记录，仅由 ctx.fs 工具操作发出；它不是文件系统监听器，会错过所有外部写入。转发它还需要运行时插件、运行时闭包重建以及新的协议通知，而覆盖范围不如原生监听器。它仍是 harness 内部的写观察权威。

### 为何不在运行时内监听（chokidar）并通过 JSON-RPC 推送？

上游已为技能根目录使用 chokidar，但桌面运行时是单可执行闭包；在那里增加监听器意味着每次变更都要重建运行时并扩展协议。Rust 宿主中的原生监听器保持运行时不变，随管理器生命周期启停，并天然获得 generation 作用域。

### 为何不用轮询？

规范优先使用可用的真实文件系统监听器；notify 在 macOS 上使用 FSEvents，监听失败时管理器降级为手动刷新。

## Consequences

- 单一非权威失效管线；ctx.fs + FsVersion 仍是唯一数据权威。
- 运行时单可执行与桌面协议保持不变（无协议版本变更）。
- Rust 拥有监听器生命周期与 generation 作用域；前端按 generation 过滤作为纵深防御。
- 19 条新桌面字符串以全部七种语言发布；覆盖门保持不变。
- 重命名按删除 + 创建处理（无脆弱的内容启发式）；重命名文件不会被自动跟随。
- 编辑器草稿在运行时重启后存活；任何待保存都不会被自动重放。
- 退出守卫在任何运行时拆除前暂停，保持无孤儿保证。
