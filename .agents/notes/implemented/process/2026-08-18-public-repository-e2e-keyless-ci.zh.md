# Agent Note: 公开仓库的 e2e CI 默认无密钥运行

Status: implemented

[English](2026-08-18-public-repository-e2e-keyless-ci.md) | 中文

## 问题

上游 e2e 工作流在仓库密钥 DEEPSEEK_API_KEY_EXTERNAL 缺失时会令预检失败，因为套件在无密钥时自行跳过，而受信任事件不得虚报通过。公开仓库没有该密钥，因此每次推送到 main 都会让预检失败。

## 决定

在公开仓库中，e2e 预检改为记录 has_key 步骤输出而不是失败：没有密钥时发出警告并跳过构建与 e2e 步骤；有密钥时工作流与上游完全一致。套件自身的跳过行为保持不变。

## 备选方案

### 为什么不在公开发布前强制要求密钥？

维护者尚未为 CI 配置外部 API 密钥，令推送失败只会让默认分支持续变红，对用户没有可见收益。

### 为什么不移除或禁用该工作流？

该工作流记录了真实 API 路径，密钥一旦存在即可恢复与上游一致的行为；移除会抹掉这条路径。

## 后果

- 在维护者添加 DEEPSEEK_API_KEY_EXTERNAL 之前，推送到 main 保持通过并带有跳过警告。
- 密钥缺失或为空会表现为带警告的套件跳过，而不是工作流失败；上游在自己仓库中保留更严格的预检。
