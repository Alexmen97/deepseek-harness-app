# Agent Note：桌面端 M5C.3 已跟踪工作区更改的放弃

状态：已实现

[English](2026-08-19-desktop-m5c3-discard.md) | 中文

## 问题

M5C.2 可以在工作区与索引之间移动文件，但没有任何操作能撤销已跟踪的工作区更改。放弃是破坏性操作，因此本里程碑必须根据 porcelain-v2 状态精确定义可放弃性，对脏编辑器缓冲区进行阻止，在变异前立即重新校验当前状态，并且绝不触碰未跟踪文件或冲突解决。

## 决策

宿主新增 `git_discard_file`，运行 `git restore --worktree -- <path>`（固定 argv、强制 `--`、先做工作区包含校验，再对最新 porcelain v2 重新校验）。git 2.50.1 上的 fixture 证据确定了可放弃性模型：放弃把工作区恢复到 INDEX 版本，不一定是 HEAD——staged+unstaged（MM）变为 M. 且暂存更改保持，MD 从索引重建文件，AM 恢复索引 blob。Y = M 或 D 且 X 属于 {., M, A} 时可放弃；仅暂存（Y = .）、暂存删除（X = D，此时 restore 会失败，因为索引没有可重建的工作区 blob）、重命名/复制条目（X = R/C，单命令语义不明确，且不发明多命令恢复）、未跟踪（??）和冲突（u）全部是 UNSUPPORTED_GIT_STATE。只有工作区被改变；索引与 HEAD 保持不变。

前端只为符合条件的行显示 Discard Changes 按钮（破坏性视觉、明确标签、无障碍标签），条件由 `git-model.ts` 中相同的可放弃性规则派生。点击后打开确认对话框，显示本地化标题、相对路径、与状态一致的后果（带暂存侧变体：「将工作区文件恢复到已暂存版本；暂存的更改仍然保留」）以及 Cancel / Discard Changes。脏 CodeMirror 缓冲区会用本地化说明阻止该操作：守卫位于操作核心（`isDirty` 选项）并且绝不调用宿主——它是 UI 数据丢失守卫，不是文件系统安全边界，宿主仍然独立校验 git/路径状态（代码中已记录）。成功后，现有 M5B watcher 失效，ctx.fs 重新校验，干净缓冲区重新加载，核心立即刷新 porcelain-v2 模型与 diff；不从 Rust 注入内容。

## 备选方案

### 为什么在宿主中重新校验而不是信任被点击的行？

放弃是破坏性操作；行可能已经过期（其他工具、终端或 watcher 改变了状态）。宿主在 `git restore` 之前立即为路径重新读取 porcelain v2，因此过期的 UI 行会被 UNSUPPORTED_GIT_STATE 或 GIT_STATE_CHANGED 拒绝，UI 刷新——绝不在过期假设下执行破坏性操作。曾考虑 git 状态 token，但被拒绝：立即重新校验更简单且足够。

### 为什么不对暂存删除或重命名启用放弃？

fixture 证据表明 `git restore --worktree` 在暂存删除上失败（索引记录删除，没有可恢复的 blob），在暂存重命名上是空操作（工作区已与索引一致）。简报优先安全而非完整：这些状态是 UNSUPPORTED 而不是猜测。

### 为什么脏编辑器阻止只在前端？

Rust 宿主没有 CodeMirror 知识，且简报的信任边界说明仅前端的阻止是 UI 数据丢失守卫，不是文件系统安全边界。宿主独立校验 git 与路径状态；核心拒绝为脏路径调用宿主（DIRTY_EDITOR_BLOCK 类型化错误，不调用宿主）。

## 后果

- 一个窄化 Tauri 命令；没有通用 git/exec/shell；`--` 始终存在；在任何 git 状态读取之前强制包含校验（工作区位于仓库根之下、../、绝对路径、符号链接逃逸）。
- 未跟踪文件没有放弃/删除 UI，宿主拒绝它们；没有 git clean、没有 stash、没有隐藏备份文件、没有撤销承诺。
- 冲突绝不被触碰：`git restore` 绝不被用作偶然的冲突解决。
- 9 个新的桌面字符串以全部七种语言发布（853 键 x 7，100% 覆盖）。
- 运行时单可执行文件与桌面协议保持不变；只扩展 Tauri invoke 面。
