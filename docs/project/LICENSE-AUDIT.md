# License audit

Reference for the licensing state of the public repository and the distributed macOS artifact. The audit was performed for M3 against the pinned upstream base (see docs/project/upstream-base.json).

## Upstream project

DeepSeek Harness is MIT licensed (LICENSE, Copyright (c) 2026 DeepSeek). The desktop commits build on the upstream history and preserve it in full: the LICENSE file, the vendor licenses, and THIRD_PARTY_NOTICES.md stay intact. The desktop-specific code added on top is also MIT.

## Modifications

The two upstream source modifications are additive and documented in docs/desktop/UPSTREAM-PATCHES.md: the ConnectionController re-export and the remote namespace mount ordering fix. Both remain under the upstream MIT license with the original notices preserved; no copyright line is replaced.

## Third-party licenses by component

| Component | License | Notes |
|---|---|---|
| Vendored Cordis tree (vendor/) | MIT | Per-directory LICENSE files preserved |
| Node SEA runtime closure (workspace packages) | MIT | The closure consists of workspace packages plus external npm deps below |
| node-pty | MIT | Native pty.node embedded in the SEA snapshot |
| sharp / libvips prebuilds | Apache-2.0 (sharp) + LGPL-2.1-or-later (libvips) | libvips binaries redistribute under LGPL; the notices file records this and the source/relink route |
| Tauri and the Rust crate tree | MIT OR Apache-2.0 | tauri, keyring, rfd, os_info, base64, serde; the Rust closure is recorded in apps/desktop/src-tauri/Cargo.lock |
| @yao-pkg/pkg | MIT | Build-time only, not redistributed |
| zstd/SQLite native bindings in the runtime closure | MIT / ISC / BSD-style | Recorded through THIRD_PARTY_NOTICES.md and pnpm-lock.yaml |

## Obligations carried by the binary distribution

- MIT and Apache-2.0 components require the copyright and permission notices to accompany the distribution; THIRD_PARTY_NOTICES.md inside the repository and the release manifest reference it.
- libvips (LGPL-2.1-or-later) requires that recipients can obtain or relink the library source; the sharp prebuild embeds libvips, and the release notes point at the sharp/libvips sources for that obligation. The audit records this instead of assuming every bundled dependency is MIT.

## Generation and verification

THIRD_PARTY_NOTICES.md is generated by scripts/gen-third-party-notices.ts from the workspace manifests; the desktop workspace packages participate in that generation. scripts/verify-desktop-release.mjs fails a release whose bundle lacks the notice file alongside the app; the release workflow copies THIRD_PARTY_NOTICES.md and LICENSE into the DMG staging before creating the disk image.

## Open items

The release publish gate requires an SPDX/CycloneDX SBOM per release; its generation plan and coverage of the native libvips closure are documented in docs/project/SUPPLY-CHAIN.md. No license prevents keeping the whole project MIT.
