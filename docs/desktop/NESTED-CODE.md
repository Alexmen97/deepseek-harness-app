# Nested code audit

Every executable and native artifact inside Harness Desktop.app. The audit
is regenerated by scripts/verify-desktop-release.mjs, which fails the
release when an unexpected Mach-O or native library appears.

## Mach-O entries

| Path | Architecture | Purpose | Signing strategy | Entitlements |
|---|---|---|---|---|
| Contents/MacOS/harness-desktop | arm64 | The Tauri application | Signed after the sidecar (outside-in finish) | Hardened Runtime, allow-jit (WebKit) |
| Contents/Resources/sidecar/dsh-desktop-runtime | arm64 | The packaged Harness runtime (Node SEA) | Build-time pkg signature (Hardened Runtime), verified but never re-signed | none |

The runtime's native dependencies (sharp/libvips images, node-pty helpers)
live inside the single-executable snapshot, not as separate bundle files, so
they are covered by the sidecar signature. Re-signing a pkg executable
corrupts the embedded snapshot (the spike reproduced a V8 CodeRange abort),
so the pipeline verifies the sidecar signature and never re-signs it.

## Verification commands

```sh
find "Harness Desktop.app" -type f -exec file {} + | grep Mach-O
codesign --verify --strict --verbose=2 "Harness Desktop.app"
codesign --verify --strict --verbose=2 "Harness Desktop.app/Contents/Resources/sidecar/dsh-desktop-runtime"
spctl --assess --type execute --verbose=2 "Harness Desktop.app"
```
